# Glossary

Project-specific names, abbreviations, and terms. General technology concepts are explained in [05-CONCEPTS.md](05-CONCEPTS.md).

## Roles and people

| Term | Meaning |
| --- | --- |
| **employee** | The lowest role. May see the employee directory, departments, and projects, plus their **own** salary, attendance, and performance. |
| **manager** | May see everyone's attendance and performance. Company-wide salary queries require approval. May approve requests and read traces, logs, and metrics. |
| **admin** | Identical permissions to manager at this commit. No code path distinguishes the two. |
| **Elevated role** | Manager or admin. The term used by `requireOwnRecordOrRole` ([authorize.ts:24-27](../server/src/middleware/authorize.ts#L24-L27)). |
| **Approver** | A manager or admin acting on the Approvals page. `APPROVER_ROLES` on the client ([roles.ts:7](../client/src/lib/roles.ts#L7)). |
| **Requester** | The user whose chat turn was paused. Also the session's owner. |
| **Owner** | The user who sent the first message to a session id. Only the owner can read, continue, or delete that session. |

## Identifiers

| Term | Format | Meaning |
| --- | --- | --- |
| `employeeId` / `employeeID` | `E` + 3 or more digits, e.g. `E001` | An employee. Both spellings occur in the code. |
| `departmentId` / `departmentID` | `D` + 3 or more digits, e.g. `D001` | A department. |
| `userId` | `U001` ... | A login account in `users.csv`. Different from the linked `employeeId`. |
| `projectID` | `P013` | A project. Repeats across assignment rows. |
| `sessionId` | UUID, generated in the browser | One conversation. |
| `approvalId` | UUID, generated on the server | One paused tool call. |
| `traceId`, `spanId` | Generated by the SDK | One agent run, and one step within it. |
| `groupId` | Equals the `sessionId` | The SDK's name for the field used to tie traces to a session ([runner.ts:132](../server/src/orchestrator/runner.ts#L132)). |
| Draft id | UUID | A session id created by the client for a new chat before any message has been sent ([use-chat.ts:43](../client/src/hooks/use-chat.ts#L43)). |

## Agents

| Term | Meaning |
| --- | --- |
| **Orchestrator** | The router agent. No tools. Hands each request to one specialist or asks a clarifying question ([orchestrator.agent.ts:75](../server/src/agents/orchestrator.agent.ts#L75)). Not to be confused with the folder `server/src/orchestrator/`, which holds the runner. |
| **Domain agent / specialist** | One of the seven agents that answer questions in a single area: Employee, Attendance, Department, Salary, Performance, Project, Policy. |
| **Data specialist** | Any of the six specialists that read records from CSVs, as opposed to the Policy Agent. A term used in these docs and in the Orchestrator's prompt. |
| **Policy Agent** | The specialist that explains what the HR policies say, from retrieved passages only. It has no access to anyone's records ([policy.agent.ts:54-67](../server/src/agents/domains/policy.agent.ts#L54-L67)). |
| **Rules vs. records** | The Orchestrator's routing distinction: what a policy says (Policy Agent) versus what a person's data says (a data specialist). |
| **Plain variant** | An agent whose final output is free text. Used by text mode. |
| **Structured variant** | The same agent with `outputType: StructuredResponseSchema`, named with the suffix "(Structured)". Used by JSON mode. |
| **Root agent** | The agent a run starts from: `orchestratorAgent` or `orchestratorAgentStructured`. Needed again to restore a paused run ([runner.ts:194-195](../server/src/orchestrator/runner.ts#L194-L195)). |
| **Classifier agent** | A small agent used only inside a guardrail to return booleans: Input Safety Classifier, Sensitive Info Classifier, Groundedness Classifier. |
| **Hand back** | A specialist handing off to the Orchestrator because part of the request is outside its domain. |
| **Borrowed tool** | An employee or department lookup tool included in another specialist's tool list so it can resolve names to IDs itself. A term used in these docs, not in the code. |
| **Identity note** | The sentence appended to some agents' instructions giving the caller's employee ID and role ([salary.agent.ts:44-48](../server/src/agents/domains/salary.agent.ts#L44-L48)). |

## Chat and responses

| Term | Meaning |
| --- | --- |
| **Turn** | One user message and the assistant's response to it. In the SDK, "turn" also means one model call within a run. |
| **Text mode** | `POST /chat` without `format` or with `format: "text"`. Plain agents, SSE replay. The only mode the React client uses. |
| **JSON mode / structured mode** | `POST /chat` with `format: "json"`. Structured agents, one JSON response. |
| **`format`** | The request field selecting the mode. Also stored on each approval so resume uses the right root agent. |
| **Replay / simulated stream** | Sending an already-complete answer as SSE in 4-character chunks 15 ms apart ([chat.controller.ts:68-69](../server/src/controllers/chat.controller.ts#L68-L69)). |
| **Token** | Two meanings. (1) A chunk of text in an SSE event, `{"token":"..."}`: here just 4 characters, not a model token. (2) The JWT. |
| **`[DONE]`** | The final SSE event marking the end of a reply. |
| **Decline** | The fixed sentence returned when a guardrail trips. Returned with HTTP 200 and saved as an assistant message. |
| **`RunOutcome`** | The runner's return type: `completed` or `needs_approval` ([runner.ts:48-58](../server/src/orchestrator/runner.ts#L48-L58)). |
| **`ChatSendResult`** | The client's view of a `POST /chat` response: `streamed`, `reply`, or `approval` ([api.ts:99-103](../client/src/lib/api.ts#L99-L103)). |
| **Recent history** | The last 20 messages of a session, which is all the model is given. |
| **Seed** | The messages and waiting list passed through router state when a new chat first gets its own URL ([types/chat.ts:17-23](../client/src/types/chat.ts#L17-L23)). |
| **Pending (message)** | An assistant bubble with no text yet, shown as a skeleton. |
| **Waiting** | The client's list of this chat's paused tool calls (`WaitingApproval[]`). |

## Approvals

| Term | Meaning |
| --- | --- |
| **HITL** | Human in the loop. |
| **Sensitive tool** | A tool with `needsApproval`. At this commit: the six company-wide salary tools. |
| **Interruption** | The SDK's term for a tool call waiting for approval. |
| **Pause / resume** | Stopping a run at an interruption and later continuing it from saved state. |
| **Serialized state** | The SDK `RunState` as a string, stored in `approvals.serialized_state`. |
| **Decision** | Approve or reject, with an optional message, posted to `/approvals/:approvalId/decision`. |
| **Claim** | The conditional update that moves an approval out of `pending` exactly once ([runner.ts:176-188](../server/src/orchestrator/runner.ts#L176-L188)). |
| **Company-wide** | Data about all employees or comparisons between them (totals, averages, rankings, ranges, exports), as opposed to one person's record. |
| **Own record** | A record whose `employeeId` equals the caller's. |

## Guardrails

| Term | Meaning |
| --- | --- |
| **Input Safety Guardrail** | Blocks off-topic requests and prompt injection. |
| **Sensitive Information Guardrail** | Blocks answers that leak the system's internals. Not about HR data sensitivity. |
| **Hallucination Prevention Guardrail** | Blocks answers containing facts not found in tool results. |
| **Employee ID / Department ID Format Guardrail** | Tool input guardrails that reject malformed IDs. Called "tool misuse" in file names. |
| **Search Query Guardrail** | Tool input guardrail on `search_hr_policies`: the query must be non-empty and at most 500 characters. |
| **Tripwire** | A guardrail verdict that ends the run. |
| **Reject content** | A tool-guardrail verdict that skips the tool and tells the model why, without ending the run. |
| **Fast path / slow path** | Regex check vs. classifier model call inside a guardrail. |
| **`detectionMethod`** | `pattern`, `no-tool-call`, or `classifier`: which path made the decision. |
| **Scope / out of scope** | Whether a request concerns HR data (assistant level), or whether it belongs to a given specialist's domain (agent level). |
| **Grounded / ungrounded** | Supported / not supported by tool results from the same run. Applying a stated rule to the user's case counts as grounded. |

## Data

| Term | Meaning |
| --- | --- |
| **CTC** | Cost to company: base salary plus bonus. The figure all "salary" comparisons use. |
| **WFH** | Work from home. Counts as a full attended day. |
| **Half-Day** | Counts as 0.5 attended days. |
| **Working day** | An attendance record whose status is not `Holiday` or `Leave`. The denominator of attendance percentage. |
| **Top performer** | A performance record with rating at or above a threshold, default 4.5. |
| **Allocation** | Percentage of an employee's time assigned to a project. |
| **Seed data** | The CSV files committed in `data/`. |
| **`app.db`** | The runtime SQLite database. |
| **Row vs. record vs. summary** | In stores: the raw snake_case DB row, the camelCase object, and the reduced object safe to return from an API. |

## Policy knowledge

| Term | Meaning |
| --- | --- |
| **Policy document** | One markdown file in `data/policies/` with frontmatter (`title`, `policy_id`, `version`, `effective_date`, `owner`) and numbered `##` sections. |
| **Policy ID** | An identifier from frontmatter such as `HR-POL-001` or `FIN-POL-001`. Shown to the model, not used as a key. |
| **Source** | A policy document's file name, as stored in `knowledge.chunks.source`. |
| **Chunk** | One stored piece of a policy document: usually one section, sometimes two or three tiny ones merged. The unit that gets an embedding. |
| **Label line** | The first line of every chunk's text, for example `Leave Policy (HR-POL-001, v2.1)`, so a chunk identifies its document on its own. |
| **Passage** | A chunk as returned by a search (`PolicyPassage`). What the Policy Agent reads. |
| **Embedding** | The 1536-number vector for a text, from `text-embedding-3-small`. |
| **Distance** | Cosine distance between a query's vector and a chunk's: 0 identical, larger is less similar. |
| **Top-K** | How many nearest chunks a search asks for. Default 4, maximum 10. |
| **Cutoff** | The maximum distance a result may have, 0.75. A noise filter, not a relevance test. |
| **Ingestion** | Running `npm run ingest:policies`: chunk every policy document, embed the chunks, replace the table's rows. |
| **Dry run** | Ingestion with `--dry-run`: chunk and print only. |
| **`knowledge.chunks`** | The Postgres table holding chunks and embeddings. |
| **Vector DB / vector pool** | The Postgres database with pgvector, and the `pg` connection pool to it. |
